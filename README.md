# Кинотеатр — админка (PyQt6 + SQLite)

Учебное приложение баз данных: администратор ведёт фильмы, залы, сеансы, продаёт и возвращает
билеты, смотрит информацию по конкретному залу, выполняет запросы реляционной алгебры,
обменивается данными через XML и анализирует продажи в OLAP-кубе.

## Запуск

```bash
uv run cinema      # или: make run
```

При первом запуске в корне проекта создаётся `cinema.db` и заполняется демо-данными
(16 фильмов, 4 зала, ~1000 сеансов за 45 дней назад и неделю вперёд, ~58 000 билетов).
Другой путь к базе можно задать переменной окружения `CINEMA_DB`.

## Вкладки

| Вкладка | Что умеет |
|---|---|
| Сеансы | расписание с фильтром по залу и дате, добавление/изменение/удаление, копирование сеанса на другое время |
| Билеты | продажа через схему зала (несколько мест сразу), возврат, редактирование, фильтры по дате/сеансу/статусу |
| Информация о зале | карточка зала, статистика за период, фильмы зала, сеансы на дату и схема заполнения выбранного сеанса |
| Фильмы, Жанры, Залы, Покупатели | справочники: добавление, изменение, удаление, поиск |
| Запросы (РА) | 28 запросов по операциям реляционной алгебры; SQL можно править и выполнять |
| OLAP-куб | ETL в звёздную схему, сводная таблица: строки × столбцы × мера, срезы, экспорт в CSV/XML |
| Журнал | изменения фильмов, сеансов и билетов, записанные триггерами аудита |

Меню «Файл»: импорт/экспорт XML, пересоздание БД (с демо-данными или пустой).

## Соответствие пунктам задания

1. **ER-модель → реляционная модель** — `docs/er_model.md`, `src/cinema/db/models.py`.
2. **Реализация в СУБД** — SQLite; таблицы, ограничения CHECK/UNIQUE/FK, индексы — `models.py`.
3. **Заполнение** — `src/cinema/db/seed.py`.
4. **Запросы реляционной алгебры** (селекция, проекция, объединение, пересечение, разность,
   декартово произведение, соединение, группировка — минимум по 3 на каждую) — `src/cinema/db/queries.py`.
5. **Триггеры и процедуры** — `src/cinema/db/ddl.py` (16 триггеров, 2 представления),
   `src/cinema/db/procedures.py`, пользовательские SQL-функции `occupancy`, `end_time`,
   `price_multiplier` — `src/cinema/db/engine.py`.
6. **Клиентское приложение** — `src/cinema/ui/`.
7. **Импорт/экспорт XML** — `src/cinema/db/xml_io.py` (связи по естественным ключам,
   повторный импорт не создаёт дублей, ошибочные строки попадают в отчёт).
8. **Хранилище и OLAP-куб** — `src/cinema/db/olap.py`, `src/cinema/ui/tabs/olap.py`.

> В SQLite нет `CREATE PROCEDURE`: триггеры и представления реализованы средствами СУБД, а логика
> процедур (`sell_tickets`, `cancel_ticket`, `clone_session`, `hall_report`, `film_revenue`) —
> транзакционными функциями на Python и пользовательскими SQL-функциями.
